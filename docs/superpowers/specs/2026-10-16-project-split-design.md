# 训练项目与机器人 Agent 推理项目拆分设计

**状态：** 待用户审阅；当前仅为设计稿，尚未移动或修改实现代码。

## 目标

把当前混合项目拆成两个各自拥有 Git 根目录、安装配置、运行说明和测试入口的项目：

1. `world-model-training`：负责模型训练、数据采集/导入、训练过程评估和训练实验配置。
2. `world-model-agent-lab`：保留当前仓库，负责世界模型推理、机器人与仿真、Agent、规划、ROS 2、实验监控和命令客户端。

两个仓库作为相邻目录放在同一个工作区。训练项目只依赖第二个项目提供的模型定义、权重读取与数据契约；运行时项目不能反向导入训练模块。新训练仓库从拆分时的源码快照初始化，当前仓库的既有 Git 历史不重写。

## 盘点依据

- `src/wmal/training/` 包含传统动力学、G1 运动网络、视觉世界模型、具身 RSSM、训练 CLI、优化器/检查点、训练评估及进度工具。
- 训练不是独立闭包。训练代码直接使用 `src/wmal/models/` 的网络和模型格式、`src/wmal/datasets/` 的数据集格式，也使用 `src/wmal/agents/prediction_contracts.py` 中的推理契约。
- 推理端不需要训练模块；模型服务、机器人、Agent、规划、仿真与监控代码可以留在当前项目。
- 现有训练入口和运行入口共用一个 `pyproject.toml`、一套配置目录与环境文件；许多脚本按各自项目根目录解析配置、模型、机器人资源和输出路径。
- 当前工作树含用户已开始的 Agent 命令客户端及监控改动。本拆分须保留这些工作，并将其归入推理与机器人项目。

## 项目边界

### `world-model-training`

拥有训练循环、训练 CLI、优化器/续训检查点、训练进度、训练专属评估、训练配置、训练/数据导入命令、相关文档及训练测试。首批训练族包括状态/关节动力学、G1 运动网络、RGB 视觉模型、具身 RSSM 和 UniFoLM 数据/训练适配器。

采集或闭环评估需要 MuJoCo 时，通过推理项目的可选仿真能力完成；训练包基础安装不要求 ROS 2、ONNX Runtime 或整套机器人运行环境。

### 当前 `world-model-agent-lab` 仓库

保留共享模型实现与在线推理所需的网络配置、模型加载器、校准和预测接口；保留数据 schema、episode/profile 契约及必要读写器；保留机器人、Agent、技能、规划、环境、MuJoCo、ROS 2、监控服务、Web 客户端和本地任务运行器。现有 Agent 命令客户端及相关未提交改动归此项目。

训练和推理共同使用的 `wmal.models`、数据契约与预测契约在此项目只维护一份，作为稳定、可版本化的训练依赖。训练项目的可安装说明先安装此项目的模型运行依赖，再安装训练项目。

## 初步文件归属

训练仓库从当前源码快照抽取：

- `src/wmal/training/`，拆分后放入训练发行包。
- 训练、采集、数据导入/转换及训练评估入口，包括 `train.py`、`train_motion_network.py`、`train_neural_dynamics.py`、`visual_world.py`、`embodied_world.py`、`prepare_wma_dataset.py`、`train_unifolm_wma.py`、`collect.py`、`collect_stack_block_visual.py` 和 `evaluate.py`。入口搬迁时要检查混合评估脚本的 MuJoCo 可选依赖。
- `configs/training/` 和训练专属测试；跨训练/推理 API 的兼容测试放在训练仓库。
- 训练指南和训练流程文档。当前仓库的 README 继续作为推理项目的独立入口；训练仓库提供自己的 README。工作区级入口如有需要，放在两个仓库之外，不把第三个总项目引入 Git。

推理仓库保留 `src/wmal/models/`、`datasets/` 中推理需要的数据契约、`agents/prediction_contracts.py`、所有机器人/Agent/规划/仿真/监控代码，以及模型和机器人资源。运行入口、任务配置、机器人配置、`robots/assets/`、`models/unitree_g1_velocity_policy.onnx`、ROS 2 接口及运行测试归此项目。

最终清单要以静态 import 与测试依赖扫描为准；混合测试按实际责任拆分，不因文件名机械搬迁。研究背景和共享架构说明可以留在推理仓库，避免引入第三个仓库。

## 打包和导入边界

- 两个发行包继续使用 `wmal.*` 兼容导入路径：训练仓库拥有 `wmal.training`，推理仓库拥有共享模型与运行模块。
- 需要用 Python namespace package 或等效的可验证配置让两个发行包安装后可共同提供 `wmal.*` 子包；不得在两个仓库复制 `wmal.models`、数据 schema 或预测契约。
- 推理项目声明轻量模型运行依赖和按需的 `simulation`、`walking`、`monitor` 等 extras。训练项目为 PyTorch/NumPy 等训练依赖提供独立 extras；只有数据采集/仿真入口才要求仿真依赖。
- 本地工作区安装顺序和兼容版本在两边 README 明确记录。正式远程分发地址及发布流程不在本次设计范围内。
- `embodied_trainer.py` 当前通过源码相对路径计算模型与契约文件哈希；拆分后需要改为基于已导入模块路径或资源 API 定位，保持哈希覆盖的文件集合及语义可追溯。

## 配置、数据与本地资产

- 两个项目各自拥有 README、`pyproject.toml`、依赖/环境说明、测试命令和项目内配置。训练默认配置从训练仓库根解析；机器人运行配置与资产从推理仓库根解析。
- 训练数据、原始数据、checkpoint、校准文件、视频与 `runs/` 结果不复制进 Git。拆分前检查当前 ignored 文件；只移动受版本控制且归属明确的清单/文档，不覆盖或删除用户本地数据。
- 将根 `.gitignore` 规则分别迁入两个仓库，确保嵌套的 `data/`、`runs/`、训练权重、构建目录和 ROS 2 生成文件继续被排除。
- 文件搬迁后检查所有脚本默认路径、资产查找、配置相对路径和训练 checkpoint 的共享源码哈希；需要时保留清晰的兼容参数，不在代码中硬编码本机绝对路径。

## Git 与迁移方式

- 当前仓库继续作为 `world-model-agent-lab`，保持其 `.git`、分支和已有改动；不把另一个 `.git` 嵌进它的目录，也不建立带 gitlink 的第三个总仓库。
- 在当前仓库旁创建 `world-model-training/` 作为独立仓库，以经过审阅的拆分快照作为初始提交；不改写当前仓库历史。源文件原有历史仍可在当前仓库的旧版本中查阅。
- 不配置远程地址、不推送、不发布包。只有用户另行给出目标远程后才设置 remote。
- 拆分时分批迁移文件，先建立两个发行包和导入边界，再迁移入口/配置/测试/文档，最后移除当前仓库的训练实现并做双仓验证。任何一步失败都可由 Git 快照和未提交状态恢复。

## 验收标准

1. `world-model-agent-lab/` 与 `world-model-training/` 各有独立 `.git` 根、`pyproject.toml`、README 和测试入口；没有嵌套仓库或未说明的 gitlink。
2. 训练端可以通过记录明确的本地安装步骤安装共享模型 API 和训练 extras；训练 CLI 可显示帮助，模型/数据契约 import 正常。
3. 推理仓库中不再包含训练循环或训练 CLI，也没有模块反向导入 `wmal.training`；Agent、机器人、仿真与监控的入口仍可运行。
4. 两个发行包共同安装后，`wmal.models`、`wmal.datasets`、`wmal.agents.prediction_contracts` 与 `wmal.training` 均能解析，检查点/数据 schema 未改变。
5. 训练和推理两边的可运行单测分别通过；与 MuJoCo、ROS 2、GPU、外部数据或浏览器有关的检查明确列出运行条件和结果。
6. 当前工作树已有的 Agent 命令客户端、监控 UI、API、任务运行器和视频录制改动完整保留在推理项目。
7. ignored 数据、实验输出和本地权重没有被覆盖、复制进 Git 或误删；拆分后的使用说明明确给出模型/数据路径。

## 不在本次拆分范围

- 训练算法、网络结构、模型 schema、预测/反馈语义或 Agent 行为的改进。
- 新训练数据生成、模型重训、仿真性能结论、真机验证或部署。
- 配置远端仓库、推送代码、发布 Python 包或合并分支。

## 自审与待确认项

- 自审确认了训练到共享模型 API 的单向依赖；推理侧无需训练模块，因此没有循环依赖设计。
- 共享源码哈希、脚本默认路径、环境 extras、数据/权重忽略规则是迁移中最容易遗漏的四类兼容点，已列入实施和验收要求。
- 本设计默认新训练仓库放在当前项目目录的相邻位置，目录名为 `world-model-training`，当前仓库继续命名为 `world-model-agent-lab`。如需其他父目录或仓库名，请在批准设计时指出。
- 本设计尚未运行拆分后测试；目录、包结构和实现改动只有在用户批准本设计后才开始。
