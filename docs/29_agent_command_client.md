# 本地 Agent 指令客户端运行指南

入口 `scripts/agent_command_client.py` 将指令、世界模型预测、MuJoCo 执行、实时画面和每个任务的 MP4 接到同一浏览器页面。它使用本地文件，不需要 API 或密钥。旧的只读监控入口见 [实验监控指南](24_agent_monitor.md)；视觉数据采集、训练和校准流程见 [视觉世界模型指南](23_visual_world_training_and_agent.md)。

## 启动前准备

在包含本次客户端代码的仓库根目录运行，使用已安装本项目依赖的 Python 环境。默认计算设备为 CPU；本地仿真需要 MuJoCo、NumPy，G1 行走另需 ONNX Runtime，神经世界模型需要 PyTorch。视频导出要求系统能找到 `ffmpeg` 和 `ffprobe`。

- **G1 行走模式**：`--g1-config` 指向实验 JSON，包含 `world_model.factory`、`world_model.config` 和 `planner`；checkpoint 必须实际存在，版本、状态/动作格式及动作时长必须兼容。仓库还须有 `models/unitree_g1_velocity_policy.onnx` 底层运动策略。
- **双关节模式**：同时传入 `--visual-checkpoint` 和 `--visual-calibration`。checkpoint 训练场景必须是 `stack_block`，摄像机、图像尺寸、肩/肘关节顺序、目标增量动作及控制周期须兼容本地工作台。独立校准文件必须与模型版本和控制语义匹配，预测步长不能超过训练与校准共同支持的上限。该模式执行受限双关节目标，不代表已经具备抓取或堆叠能力。

配置中的相对 checkpoint 路径以配置文件所属仓库根目录解析；找不到仓库标记时使用配置所在目录。视觉文件的相对路径也采用这个基准。使用绝对路径最清楚。训练产物通常不随 Git 分发；历史文档列出过某个权重路径，不表示本机已有该文件。

某类资产缺失或不兼容时，客户端仍可启动，页面显示不可用原因，只允许下发实际注册的模式。启动成功不等于机器人任务成功。

## 启动客户端

下面命令中的模型路径应替换为本机真实文件。`--run-dir` 相对 `--runs-root`，必须是新的或空的可见子目录，不能覆盖已有实验。

```bash
PYTHONPATH=src python scripts/agent_command_client.py \
  --g1-config /absolute/path/to/g1_agent_config.json \
  --visual-checkpoint /absolute/path/to/visual/best.pt \
  --visual-calibration /absolute/path/to/visual/calibration.json \
  --runs-root /absolute/path/to/runs \
  --run-dir agent_client_run1 \
  --port 8765 --device cpu --g1-cycles 30
```

只验证 G1 时，可省略两个视觉参数；页面会明确显示双关节模式缺少资产。默认按仿真时间实时运行，`--no-realtime` 可取消墙钟等待；视频时长仍使用仿真时间。`--max-pending 8` 控制排队容量，`--video-fps 15` 控制输出视频帧率。程序启动后打印完整浏览器地址，通常为 `http://127.0.0.1:8765/?run=<run_id>`；按打印地址打开即可选中当前运行。

macOS 上不要照搬 Linux 的 `MUJOCO_GL=egl` 设置。应使用当前系统可工作的 MuJoCo 渲染配置；无原生查看器不等于不需要图像渲染支持。

## 下发动作、查看预测与取消

在“Agent 指令与仿真任务”面板选择可用模式，输入以下任意一条指令，点击“下发动作”。当前自然语言输入采用有限中文语法，单位和格式按示例填写；它不接受任意复杂任务描述。

| 模式 | 指令样例 | 含义 |
| --- | --- | --- |
| G1 | `前进 0.4 米` | 从该任务实际开始时的姿态向前移动 |
| G1 | `后退 0.2 米` | 从任务开始时的姿态后退 |
| G1 | `左转 30 度` 或 `右转 30 度` | 从任务开始时的朝向转动 |
| G1 | `到达坐标 0.4 0.0 朝向 30 度` | 到达世界坐标并调整朝向；可省略朝向 |
| 双关节 | `肩关节到 0.45 rad，肘关节到 0.95 rad` | 设置肩、肘目标角度 |

也可留空文字输入，展开结构化参数设置坐标或关节目标。G1 从当前实际位置开始的完整路径上限为 2 米，转向范围为 ±180 度；肩关节范围为 0.05–0.65 rad，肘关节为 0.55–1.15 rad。双关节预测步长以页面能力提示为准。

任务卡展示服务端状态、预测证据和真实观测，实时画面来自正在执行的 MuJoCo 场景。排队任务按顺序执行，同一模式的连续任务沿用实际状态；切换模式会关闭原场景并建立另一场景，再切回时建立新场景。

点击任务卡的“取消任务”提交取消请求。排队任务可直接取消；运行任务在安全控制边界停止，推理或编码尚未返回时可能需要等待。应以服务端最终状态确认停止，不以点击按钮或画面暂时不变作为完成依据。终端 `Ctrl+C` 或进程退出信号也会请求有界关闭。

## 下载 MP4 与查找产物

任务停止后仍需完成编码与视频校验。视频状态为就绪后，可在任务卡播放，并点击“下载完整 MP4”。失败、取消或没有运动的任务也可能生成相应的真实片段；任务成功与视频就绪是两个独立结果。若编码或最终画面获取失败，页面会显示失败状态，不应把临时文件当作完整视频。

编码使用仿真时间，保留动作前首帧与停止后末帧。队列繁忙时可能丢弃中间采样并延续上一帧以保留时长，元数据会记录丢帧；“完整”表示任务时段的视频文件完成导出，不表示逐个物理步均无损录制。

```text
<runs-root>/<run-dir>/
├── run_manifest.json          # 本次客户端运行信息与能力
├── events.jsonl              # 运行入口事件，可被历史监控发现
└── .agent_tasks/              # 隐藏，避免每个任务被误列为独立 run
    └── <task_id>/
        ├── manifest.json      # 指令、状态、进度、结果及视频元数据
        ├── events.jsonl       # 预测、真实观测与生命周期事件
        ├── video.mp4          # 成功完成编码与校验后出现
        └── …                  # 模式专属日志和预测产物
```

临时视频使用 `.mp4.part`；只有完成编码、解码和时长检查后才改名为 `video.mp4`。任务结果保留在各自目录，不应手工修改运行中的任务文件。

## 验证范围

本客户端用于本地模型和 MuJoCo 仿真。模型可加载、单元测试通过、浏览器能打开、真实任务已执行、视频可解码是不同层次的验证。实际任务仍可能因模型预测误差、控制约束或预算耗尽而失败，必须查看任务结果。现有实现与本地测试没有证明真实机器人硬件执行、ROS 2 联调或 sim-to-real 能力；模型集成分歧和校准区间也不等同于任务成功概率。
